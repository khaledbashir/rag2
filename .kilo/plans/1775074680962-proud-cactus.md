# Tomorrow's Debug & Fix Plan

## 1. Why `UniverPreview` Isn't Rendering
**Root Cause:**
The `useRfpServerPreview` hook relies on `editableSpecs` wrapped in a `useMemo` that continuously returns a new reference when the underlying spec references change or re-render loops occur. This constantly resets the `DEBOUNCE_MS` timer, and eventually calls `abortRef.current.abort()` on the ongoing fetch request before it completes, causing a silent `AbortError` (caught and ignored inside the hook). Since it aborts without setting `data` or `error`, `serverWorkbookData` remains `null`, causing the UI to silently fall back to the old client-side `<UniverSpreadsheet>`.

**Action:** 
- In `hooks/useRfpServerPreview.ts`, change the dependency array to stringify or deeply compare the `specs` array so the debounce timeout isn't interrupted by stable-but-new-reference updates. 
- Add `flex flex-col` to the wrapper `div` in `RfpAnalyzerClient.tsx` holding `<UniverPreview>` to ensure it doesn't suffer a 0-height container abort.

## 2. Eliminate Client-Side Mismatch Patch
**Root Cause:**
We were passing client-calculated pricing arrays into the server export endpoint, trying to force it to match.

**Action:**
- In `/api/rfp/pipeline/scoping-workbook/route.ts`, remove the 50-line `clientDisplays` mapping logic.
- Rely purely on `specs` (passed from the client as `editableSpecs` that contain `selectedProductName`/`pixelPitchMm`) to run through `generateRateCardExcel` and `generateScopingWorkbook` exactly like the preview endpoint does. This guarantees **One Source of Truth**.

## 3. Manual Dropdown Wiring in Univer
**Root Cause:**
`convertWorkbook` explicitly drops Excel's `dataValidation` objects because `@univerjs/preset-sheets-data-validation` uses a vastly different internal plugin JSON schema that is hard to construct manually.

**Action:**
- In `UniverPreview.tsx`, listen to `univerAPI.Event.SelectionChanged`. 
- When a user selects a cell in the "Product" column of the "LED Cost Sheet", use the facade method `getActiveRange()?.getCellRect()` to get the pixel X/Y coordinates of the active cell on the canvas.
- Render an absolute-positioned React `<select>` overlay precisely over that cell using those coordinates, populated with the `availableProducts`.
- When an option is picked, manually update the cell value via `univerAPI` and trigger `onCellEdit` to cascade the changes back to `editableSpecs` (which triggers a full server recalculation).
